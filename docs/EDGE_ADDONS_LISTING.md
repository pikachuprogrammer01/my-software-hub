# Edge Add-ons 填写指南（v1.6.0）

本文件用于 Edge Add-ons Partner Center 的商店信息和“隐私实践/数据使用”申报。后台字段名称可能随 Microsoft UI 调整，按语义选择等价选项即可；不要把 Sentry 描述成广告分析或用户画像。

## 1. 单一用途

建议填写：

> 从网页表格中扫描、预览、去重并导出结构化数据。

功能描述中可补充：

> TableFlow 在浏览器本地处理表格数据；用户可选择发送匿名错误诊断以帮助修复扩展问题。扩展不用于广告、用户画像或跨站跟踪。

## 2. 隐私政策 URL

需要填写一个无需登录即可访问的 HTTPS URL，内容对应 [`docs/PRIVACY_POLICY.md`](./PRIVACY_POLICY.md)。你提供的公开 Gitee 地址是：

```text
https://gitee.com/pikachuprogrammer01/my-software-releases/tree/table-flow
```

请先把隐私政策文件放入 Gitee 的 `table-flow` 分支，再将该地址提交到 Edge。更稳妥的最终地址是该文件的直接页面，例如：

```text
https://gitee.com/pikachuprogrammer01/my-software-releases/blob/table-flow/PRIVACY_POLICY.md
```

如果暂时只使用你给出的分支目录地址，也必须确认页面中能看到隐私政策文件，并且无需登录即可打开。

## 3. 数据使用/隐私实践

TableFlow v1.6.0 的实际行为对应以下选择：

| 后台问题 | 建议选择/填写 |
|---|---|
| 是否收集用户数据 | **是**。因为开启匿名诊断时会向 Sentry 发送错误诊断事件 |
| 数据类型 | **错误报告/崩溃报告（Error reports / crash data）**；如果后台将其归入“诊断信息”，选择该等价项 |
| 是否收集网页内容、个人信息、健康/财务信息、身份认证信息 | **否** |
| 数据用途 | **扩展功能/稳定性（App functionality / diagnostics）**；不要选择广告、营销、出售数据或个性化 |
| 是否出售或转移给广告商 | **否** |
| 第三方处理方 | **Sentry**，用于错误聚合、版本回归和稳定性排查 |
| 是否支持关闭 | **是**，扩展设置 → 隐私与诊断 → 发送匿名错误诊断 |

如果后台把“错误报告”细分为“崩溃报告”和“性能/分析”，只勾选错误/崩溃诊断；当前实现没有 Session Replay、录屏、广告分析，也没有往诊断链路发性能追踪。

> **v1.6 新增能力（申报时不要漏也不要夸）**：调试控制台提供**只本地**的 DOM 快照导出与网络取证（域名/状态/耗时），
> 默认关闭、不上传任何服务器（详见 `docs/PRIVACY_POLICY.md` §3.1）；它不属于“收集用户数据并传给我们或第三方”，
> 但属于“可读取页面内容并写入本地文件”，如果后台问到“是否访问页面内容/剪贴板/下载”，按实际能力如实选择并在理由里注明“仅本地”。

## 4. 权限说明

在权限理由字段使用以下简短说明：

- `storage`：保存用户偏好、采集缓存和匿名错误诊断开关；
- `scripting`：在用户授权的标签页注入表格扫描和浮动面板脚本；
- `activeTab`：响应用户点击，在当前标签页执行扫描；
- `tabs`：由 Background 获取当前标签页/框架关系并打开用户主动点击的更新链接；
- `<all_urls>`：支持任意网站及嵌套 iframe 的表格识别，并发起固定的更新、许可证和 Sentry
  诊断请求；调试控制台的样式代理也经 Background 取回页面**自身已加载**的样式表（仅用于本地
  快照回放，不上传）；
- `file:///*`（host_permissions 与内容脚本 matches 均含）：在 file:// 本地 HTML 页面上扫描
  表格（需用户已在浏览器允许访问文件 URL）。

## 5. 提交前核对

- 隐私政策 URL 可匿名访问，且文案与扩展设置中的诊断开关一致；
- 商店勾选项只包含错误/崩溃诊断，不勾选网页内容、个人信息、广告或行为分析；
- 生产包不包含 `.map` 文件和开发测试入口（2026-09-24 实测提醒：反「无限 debugger」补丁属**设计内的 MAIN world 内容脚本**，会对页面自身含 `debugger` 的计时器回调用 `new Function` 重编译，单一用途描述里应当作“开发者诊断能力”而不得声称“生产包无任何动态代码入口”；发布包内其他 `new Function` 出现点需逐处定性，见 `docs/PLUGIN-LOADER-SPEC.md` §5.1/§14.1）；
- 先上传 `v1.6.0` 包，再在后台提交审核（上传前先核对商店后台当前已上架版本，避开重复提交）；审核期间不要更换 DSN 或扩大事件字段；
- Sentry 项目已配置访问控制、数据保留期限和删除流程；release 名按构建时 `package.json` 版本写入，只有该版本的 artifact 已上传后可以 `release=<版本>` 检索（当前已上传 artifact 的 release 仍为 1.4.x，见 `docs/sentry-observability-implementation.md`）。
