# 常见问题

**Q：起服务报端口被占用。**
A：`AUTOMATION_MANAGER_PORT=4788 npm start` 换一个。端口只绑回环地址，不存在暴露到局域网的问题。

**Q：任务失败，退出码 3，日志里写 `playwright_cli_missing`。**
A：录制链路需要一次依赖安装：`cd manager && npm install`（走系统 Chrome，不额外下载浏览器内核）。装完再跑就好了。

**Q：改了前端，界面却没变化。**
A：`manager/public/` 是入库的构建产物，改 `manager/web/src/` 后必须 `npm run build`，否则界面与后端静默失同步。`npm run check` 里的 `check:artifact` 就是专门抓这件事的。

**Q：定时任务失败会不会天天弹通知？**
A：不会。launchd 触发的失败才弹 macOS 通知，且**同一任务同一原因当天只提醒一次**。在界面里点运行、或在终端手跑都不弹——当场就能看到结果。

**Q：机器被强杀过一次，之后那个任务一直 `skipped`。**
A：并发锁里记着持有者 pid。上一轮留下的陈旧锁会被接管，运行记录带上 `lockStale: true`，而不是把"永久停跑"伪装成"今天无事可做"。用 `manager/automation-log.mjs --task <id>` 看这个任务的历史就能确认。

**Q：页面今天确实没东西可领，能不能不报警？**
A：能，而且这是产品鼓励的约定：脚本遇到"无事可做"应当**成功退出并写明原因**，而不是返回失败。管理器的状态判定就是照这个约定设计的，内置演示站点的文案与判定标记刻意保持一致，就是为了把它演示清楚。

**Q：会不会不小心把站点地址、账号提交进仓库？**
A：边界靠两个目录名成立：`private/`（你自己的站点适配层）和 `var/`（登记表、登录态、浏览器 Profile、日志与取证截图）都由**入库的** `.gitignore` 整棵排除，克隆下来是空的。之所以不用 `.git/info/exclude`，是因为后者不随仓库走，重新克隆后就没了，再来一次 `git add -A` 就把站点名和账号写进 git 历史——而历史是事后清不掉的东西。

**Q：怎么迁到另一台机器？**
A：代码 `git clone`，数据拷 `var/` 整个目录过去。注意 `var/` 里含登录态与 Chrome Profile，等同你的登录凭据，走加密通道，别用聊天工具传。

**Q：能不能删掉一个任务的所有痕迹？**
A：界面上移除定时不会动脚本、凭据和日志（这是刻意的，防止误删）。要彻底删除，逐项清单在仓库的 `manager/README.md` 里，因为它涉及"哪些文件该一起清掉"的具体路径，文档比界面提示可靠。

**Q：有 Windows 或 Linux 版吗？**
A：没有。定时、凭据、进程托管三件事分别建立在 launchd、macOS Keychain 和系统 Chrome 上，没有跨平台路径。

**Q：它能自动化任何网站，你不管合规吗？**
A：不管，而且明说不管。工具本身是通用的，**目标站点的服务条款是否允许脚本化访问由使用者自己确认并承担后果**；作者未做这项评估，也不为任何具体站点的用法背书。示例只用仓内自带的本地演示站点。
