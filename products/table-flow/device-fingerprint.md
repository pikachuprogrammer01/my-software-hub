# 设备特征采集披露（Device Fingerprint Disclosure）

- 适用版本：TableFlow v2.1.0
- 最近更新：2026-11-22（移除续费通知和 Push 登记；保留既有设备身份与在线权益核验）
- 关联文档：[隐私政策](https://hub.pikachu01.me/table-flow/privacy) §3.2、开发仓 `docs/client-integration.md` §14

本文说明扩展处理的设备字段、身份凭据、额度记账标识、用途、保存位置与用户控制。

## 1. 用途与身份边界

免费翻页额度由自有授权服务器 `license.pikachu01.me` 记账。首次注册上传设备特征用于反滥用判断；恢复旧账本必须提供有效访问令牌或服务端签发的强恢复秘密。公开设备码、指纹相似度及账号哈希均不能恢复或合并旧账本。

有有效强凭据的恢复不会重赠初始额度。所有身份副本与恢复 Cookie 均丢失时，不能保证恢复原设备；不能用“同一机器/同一账号”替代认证。

现有设备特征、可选账号哈希、来源 IP 哈希与历史首次赠额事实可组合用于防止重复领取。命中时新身份先不获赠额，可在「账户 → 免费额度申请」申请人工复核；不据此认领、合并或改写旧账本。单个账号或 IP 信号不单独判定，证据不足时无法保证识别同一物理设备；不新增字段、采集权限或留存期限。

## 2. 设备特征字段（共 6 项）

| 字段 | 取值来源 | 用途 |
| --- | --- | --- |
| `timezone` | `Intl.DateTimeFormat().resolvedOptions().timeZone` | 风险观察 |
| `language` | `navigator.language` | 风险观察 |
| `cpuCores` | `navigator.hardwareConcurrency` | 风险观察 |
| `platform` | `navigator.userAgentData.platform`，回退 `navigator.platform` | 风险观察 |
| `screen` | 屏幕宽高组成 `宽x高`，不含色深 | 风险观察 |
| `webglRenderer` | WebGL 渲染器描述 | 风险观察 |

不可得字段传 `null`，不编造占位值；首次 bootstrap 需要达到可用字段阈值。已有有效强凭据的恢复与首次 bootstrap 分别校验，不能以指纹缺项为由清掉原身份。

第 1–4 项在扩展后台读取；屏幕与 WebGL 字段由扩展自己的固定欢迎页读取并保存在 `storage.local`。安装时打开该页面；缓存不可用时允许在冷却窗口内重新打开。不会为了设备特征向用户正在浏览的网页注入采集脚本。

字段只用于注册及需要刷新设备风险观察的请求，不随每次翻页重复上报，不进入运行诊断。请求还可能携带独立 bootstrap/恢复证明；六项指纹不是完整请求体的全部字段。

## 3. 可选账号哈希

注册及需要刷新风险观察时，扩展读取当前已登录 Chrome/Edge 账号的稳定标识；优先账号 id，缺失时回退邮箱。在本地归一化并 SHA-256 后，只发送可选 `accountHash`。原始 id/邮箱不出网、不落盘、不进入日志。

服务端只保存该值的加盐二次哈希，用于风险观察，不能据此取得旧账本。未登录、账号不可得或未授权时省略该字段，不编造替代值。六项设备特征中不包含账号哈希。

## 4. 凭据、Cookie 与本地存储

服务端签发设备码、访问令牌及独立恢复凭据，连同到期时刻、family/代际和额度视图保存于扩展 `storage.local` 与 `storage.sync`。同步副本可能随浏览器账号的同步策略保留；local 在卸载时清除。设备码与访问令牌仍是服务端签发，客户端不从指纹推导。

访问令牌通过 Authorization 请求头发送，不放入余额查询 URL。恢复秘密用于原账本恢复和双阶段轮换/确认；网络或落盘失败时保留待确认材料，避免丢失原身份。额度请求携带任务、操作、请求、结果摘要及所有权代次等最小标识，用于开始扣费、续租、恢复和原请求对账，旧任务保留预留/结算/释放兼容，不发送表格单元格、表头或网页地址。

授权服务器在自己的域名下设置 `__Host-tf_recovery` / `__Host-tf_recovery_pending` 强恢复 Cookie，使用 Secure、HttpOnly 和 SameSite=None。浏览器在扩展请求的 `credentials:'include'` 模式下自动携带；扩展不申请 cookies 权限、不读取或修改 Cookie。服务器只接受精确批准的扩展 Origin。

历史公开 `device_code` Cookie 不再授权恢复；旧匿名 `tfv` 协议不能替代新设备恢复协议。清 Cookie 后是否能恢复取决于是否还保有其他有效强凭据，不能直接等同于新设备或保证额度重置。

新翻页结果保存在扩展独立任务仓库；「保留的采集任务」可恢复或清理原文，关闭原标签页或重启后仍可恢复输出。断网时也能清理原文，最小账务墓碑继续用于释放与原请求核对，并阻止迟到写入恢复已删原文，清理不撤销已经提交的结算。

## 5. 服务端保存与留存

设备特征、账号及来源网络字段由服务端加盐哈希后保存，不把 IP 以明文长期保留。观察字段的保留期以注册响应 `retentionDays` 及服务端配置为准，源码默认 180 天，实际配置及清理执行需发布时核验；源赠额预算窗口内所需证据不能提前清除。

恢复凭据有效期独立配置，源码默认 730 天，实际以服务端配置及响应为准；其摘要、版本及短期加密交付用于恢复、轮换和重试。访问令牌、强恢复凭据和设备观察字段的有效期不是同一个概念。

原始赠额、消费、操作终态与旧请求对账事实独立于观察字段留存，不因清理指纹/IP 哈希而删除或重置。恢复与额度端点不接收网页内容、账号原文或浏览历史。

平台另记录独立自动申领的首次受理时间、稳定业务标识和设备账本/赠额机会关联。只有平台已验证主体才能按同一 TableFlow 额度项目滚动 7 天第 3 笔产生管理员核对提醒；当前匿名入口缺少此绑定，保持身份未确认，不按 IP、账号观察或指纹合并人。查询、扣费、手动申领和同笔重放不计入。提醒不更改原赠额复核、已有额度和批次回执，也不新增客户端设备字段或权限。

## 6. 用户控制与权限

可在浏览器扩展与同步设置中清除扩展数据，也可在授权服务器域下清除 Cookie；清除全部有效身份材料可能使原账本无法恢复。卸载不删除服务器上已有的额度与消费事实。

扩展不出售数据，不用于广告、用户画像或跨站跟踪，不引入第三方诊断上报。设备特征不读取页面内容或第三方网站 Cookie；扩展业务所需的服务端凭据只用于自有授权服务。未新增 alarms/cookies/offscreen/sidePanel 权限。

安装或更新后可能尝试准备设备身份；正常 Pro 与有效离线授权的执行走独立分支，不依赖免费额度操作租约。不能将免费额度出网要求套用到有效离线授权。

## 7. 实现与验证入口

- 设备特征采集：`src/license/registrationFingerprint.ts`、固定欢迎页环境缓存。
- 账号哈希：`src/license/accountAnchor.ts`。
- 设备身份副本、恢复、轮换与确认：`src/license/deviceIdentity.ts`。
- 注册、额度和操作协议出网：`src/license/usageClient.ts`。
- Cookie 权限与出网边界守卫：`src/license/cookieDiscipline.spec.ts`、`src/license/outboundGuard.spec.ts`。

发布前以最终客户端包、LicenseHub 对应源码与部署配置核验上述行为；本页不替代实际发布验收。

## 联网期限与取码反馈

设备注册、强凭据恢复与额度操作使用「设置 → 表格采集 → 翻页与等待」中的「联网请求超时」（默认15秒、1–120整数秒），实际超时保留原身份与请求并提供指引。该设置只控制等待期限，不新增设备维度、上报字段、权限或接收方；激活验签和更新检查仍有独立期限。在线取码失败不会以本机离线申请码冒充平台身份；切换离线方式可在本机获取申请码。

## 在线续费核验的设备关联

在线续费通过账户入口及实际在线 Pro 操作，按当前强设备凭据、产品和实际授权绑定向 Hub 核验；不能用指纹相似度、账号或 IP 认领旧账本。扩展不申请通知权限、不查询 VAPID 公钥、不登记浏览器 Push 端点、公钥或认证材料，不监听续费 Push 以唤醒后台。

升级仅通过浏览器已有能力尽力退役旧订阅并清理本地设置，不为此获取新身份或调用 Hub 注册、注销接口；失败保持停用，不给本地离线操作新增 Hub 请求。服务端历史订阅与投递记录不由本次客户端退役删除，仍按既有服务端管理流程处理。
