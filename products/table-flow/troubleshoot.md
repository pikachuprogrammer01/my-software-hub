# 排查手册

按**你看到的现象**找条目。每条都给出：先看哪里 → 大概率是什么 → 怎么处理。

::: tip 排查前先做这一件事
有正在采集或保留的任务时，先暂停并核对已确认页数、行数和状态。识别问题再刷新、重新扫描；结果恢复从「保留的采集任务」进入，开始扣费待确认沿原任务、原请求重试。
:::

## 先定位：问题属于哪一段

TableFlow 有两条方向相反的工作流，故障现象相似但原因完全不同：

| 你在做什么 | 走哪条链路 | 本文位置 |
|---|---|---|
| 把网页上的表格**采下来**导出 | 扫描 → 选择 → 采集 → 导出 | [采集与导出](#采集与导出) |
| 把本地 Excel 的**行写进网页** | 导入 → 选目标 → 检查映射 → 逐行填充 | [Excel 填充网页](#excel-填充网页) |

判断依据很简单：**面板里选的是「采集网页数据」还是「Excel 填充网页」**。选错了模式，后面的操作都不会有反应。

## 采集与导出

### 面板显示「未检测到表格」

**先看这里**：面板空状态提示，以及页面上的表格是不是真的"画"出来了。

按可能性排序：

1. **表格还没渲染完**——页面提示「内容可能未完全加载」时，等页面稳定后点「重新扫描」。
2. **表格在折叠面板里**——先手动展开那一块，再扫描。
3. **表格是 `ul`/`li` 列表**——去「设置 → 表格采集 → 识别范围」确认「列表识别（ul/li）」已开启；如果开了还是识别成奇怪的样子，把「列表识别严格度」从「标准」放宽到「宽松」再重扫。
4. **数据只在接口里、没画到页面上**——这种采不到，属于[已知边界](/table-flow/scope)。插件读的是浏览器渲染出来的 DOM，读不到网络请求里还没上屏的数据。
5. **表格在别人的网站的小窗口里（跨域 iframe）**——默认只放行政务类域名。其他站点要在「设置 → 表格采集 → 识别范围」把「扫描所有跨域 iframe」打开，或手动把域名加进白名单。

::: warning 跨域小窗口的额外限制
跨域 iframe 里的表**不参与合并**，也不能和其他表拼成一份导出。这是浏览器的同源策略决定的，不是设置问题。
:::

### 表格识别出来了，但只有一部分行

**先看这里**：导出后的总行数，对比页面上"共 N 条"的提示。

最典型的原因是**虚拟滚动**——长列表只渲染看得见的那几行。TableFlow 会自己滚动逐屏抓取去重，但有两个前提：

- 自动翻页**关着也能**采全当前页（靠自动滚动）；
- 需要滚动才能出现的行，采集过程中**不要动鼠标滚轮**，否则会和插件的滚动打架。

如果行数对不上，用「重新扫描」后重采一次；仍然缺行，把页面滚到底再扫描，让浏览器把内容渲染出来。

### 翻页没有反应 / 翻到一半停了

**先看这里**：采集结束时的提示语。它会明说停在哪、为什么停，不会假装采全了。

| 提示 | 含义 | 处理 |
|---|---|---|
| 达到最大页数 | 首次自动采集的最大页数**包含起始页** | 配置新任务时调整最大采集页数；接续采集先核对原任务，切换自动段时输入后续翻页次数 |
| 检测到页面没有变化 | 页码变了但内容没变（"错联分页器"） | 换「手动拾取」指定真正的下一页按钮 |
| 无法确认是否已到最后一页 | 判断不了就停下来问你，而不是悄悄漏采 | 确认页面后结束采集，按提示交付已确认页 |
| 加载更多达到轮数上限 | 无限滚动类入口有独立轮数预算，触顶可续采 | 核对原任务后点继续 |

**下一页按钮不是标准写法时**：在列配置「翻页采集」中选「手动选择」，再点「去页面选择」——鼠标悬停会高亮，点一下确认。跨域小窗口里也能用（父页面投递、子窗口内拾取），30 秒无操作会自动停止。

### 预览只显示起始页几行，后续页不出现

先核对状态栏的已确认页数和总行数，再点「显示全部 … 行」。新免费任务确认开始时已经扣1次，完整预览不再设首次交付样例或扣费确认；「显示全部 / 收起」只调整范围。

若行数确实不足，核对网页实际落页和暂停原因，再继续原任务。还未完成的本页草稿不能当成已确认结果。

### 开始扣费待确认 / 输出超时

1. 开始请求超时可能发生在服务端已扣费之后。保留原任务和配置，联网后重试原开始操作，先查询原任务和原请求，不连续新建任务。
2. 扣费尚未确认时不会先采页。已确认开始扣费的任务恢复、继续、切换和重复输出不再扣费。
3. 文件生成失败或取消保存，可对同一任务重试输出；失败、零结果、结束或清理均不退还已扣次数。
4. 升级前的旧任务若显示结算待确认，只按原协议核对该任务原请求，不转换成新任务重扣。

### 暂停后可用额度没有回升

这是开始扣费后的正常状态。新免费翻页任务确认开始即扣1次，不会因暂停、关闭、自动段完成或清理退回。恢复同一任务也不再扣费，不需要为这次任务重新购买一次额度。

正常手动等待没有固定倒计时；联网确认失败时保留断点，按提示恢复原任务。升级前旧预留任务按自身提示兼容处理，不能将旧任务的释放规则套用于新任务。

### 切换模式卡在“正在确认上一页操作”

1. 在预览底部同一行「翻页模式」切换；运行、暂停或失败时均可操作。网页中央立即出现确认框，转自动时可在「接下来自动翻几页？」马上填写后续 `N` 次。
2. 系统停止后续导航，先核对上一次点击真正落在哪一页，并保存该页；未完成前确认按钮不可用，但仍可取消。不要连续点网页下一页。
3. 核对完成后，点「切换并开始自动翻页」或「切换为手动翻页」直接执行，不用另找继续。核对失败会保留结果和本页断点并暂停，先核对页面或重新选择入口。
4. 取消或 Escape 保留原模式与数据，状态保持暂停；需要时点「继续」恢复原模式。
5. 自动段完成立即暂停并留在结果预览，继续已经完成的段先填新 `N`；只是恢复未完成段则保留剩余次数。切换、失败后恢复和同任务继续均不再扣费。

### 原标签页已关闭 / 浏览器重启了

在可打开面板的网页找到「保留的采集任务」，点「恢复结果」。已确认开始扣费的任务可直接查看和输出，不再扣费，也不要求原标签仍存在；升级前旧任务仅沿原协议核对。

继续原任务需要回到任务绑定的原标签，核对来源、表格和实际落页。原标签已关闭或重启后标签身份变化时，先导出保留结果，再新建任务采后续页。不能把另一网站或另一张表的数据接到原任务。

### 想清理数据，但额度服务连不上

1. 先导出需要保留的结果。当前任务先暂停，在底部「任务操作」选「清理本次任务数据…」；历史任务在「保留的采集任务」点对应条目「清理此任务数据…」。
2. 核对确认框的任务来源、行数和无法恢复提示，点「清理本地数据」。断网也可删除本地原文，清理后不能恢复或继续此任务，已扣次数不退还。
3. 运行、导出或其他任务操作进行中时清理暂不可用，按入口旁的提示等待。仅显示「本地清理尚未完成」时点「重试本地清理」；旧任务账务兼容由系统处理，联网不会让已删原文重新出现。

### 导出失败或文件是空的

按顺序检查：

1. **有没有先采集**——导出的是「采集结果」，只扫描不采集时列表是空的。
2. **结果是否为空或不完整**——核对采集结果条数与暂停原因，必要时先导出已确认数据；免费额度不是导出行数上限。
3. **下载被浏览器拦了**——地址栏右侧如果有被拦截的下载图标，点开允许 `chrome-extension://` 来源的下载。
4. **文件名里有非法字符**——自定义文件名不要带 `/ \ : * ? " < > |`。

### 列名乱了 / 列名变成「列1」「列2」

**先看这里**：导出文件里的表头行。

原因分三种：

1. **列表型表格（`ul`/`li`）没有列名声明**——这类结构本身不带表头。去 **设置 → 模板与规则 → 列名规则** 加一条规则：选「日期」「标题链接」这类现成选项，填个你想要的列名，重扫后就按你的名字显示。
2. **表头行被当成了数据行**——合并单元格、两行表头、表头里有输入框的复杂表格容易这样。检查导出的第一行是不是被当成了数据。
3. **多级表头只保留了末级**——多级表头会拼成 `上级 > 子级` 的形式。如果你想看层级关系，看导出文件的完整表头；如果显示成单级，说明那一层没有识别到合并信息。

### 采集出来的数字变成了科学计数法（1.23E+15）

**这是 Excel 的显示行为，不是数据错了。**

订单号、身份证号、长编号这类超过 15 位的数字，Excel 会按数值处理并显示成科学计数法，**而且第 16 位之后会被抹成 0**。这是 Excel 的精度限制（IEEE 754 双精度），任何工具导出的 CSV 用 Excel 打开都会这样。

三种处理方式：

| 做法 | 效果 |
|---|---|
| 导出成 **CSV** 后用「数据 → 从文本/CSV」导入，把该列设为**文本** | 完全保真，推荐 |
| 导出成 **JSON** | 保真，但需要再转换 |
| 导出前把该列识别为文本（Excel 里提前把列格式设为文本） | 保真，但要求导出环节保留文本类型 |

::: warning 直接双击打开 CSV 一定会这样
这不是 TableFlow 能控制的——是 Excel 打开 CSV 时的默认类型推断。要用 CSV + Excel，请走「导入」流程而不是双击。
:::

### 采集结果有重复行

**先看这里**：面板上的去重开关，以及重复行是否「完全一样」。

- **完全相同的行**：去重功能没开。采集结果页有去重入口。
- **看起来一样但有细微差别**（多一个空格、全半角不同）：去重按严格比对，这类不会合并。导出后自己处理。
- **分页采集时重复**：翻页边界重复读到同一页。TableFlow 会用「行身份」判断是不是同一行——优先用 `data-id` 这类行 ID，没有就用「位置 + 文字」。如果页面每次渲染都改 ID，可能判不出来。

### 只采到了当前这一页

先确认自动翻页有没有开，再确认「翻页入口」有没有识别到：

- **下一页按钮不是标准写法**（图标按钮、无文字、自定义组件）→ 在列配置「翻页采集」中选「手动选择」，再点「去页面选择」。
- **表格在跨域小窗口里** → 可以在帧内手动点选翻页按钮，但**帧内的表不参与合并**。
- **Load More / 无限滚动** → 按新增行数推进，轮数有独立预算（单次默认 200 轮），触顶可续采。
- **列表型表格（`ul`/`li`）** → 选择独立「手动翻页采集」，每页核对后接续，见[手动模式排查](#手动模式与设置排查)。列表的具体读取范围见[场景覆盖矩阵](/table-flow/scope#场景覆盖矩阵)。

### 合并单元格的样式丢了

合并信息按「采集那一刻的渲染状态」记录。如果是虚拟滚动表格，**已经滚出窗口的合并可能补不全**——这是已知限制，因为滚出视口后 DOM 已经被回收，合并信息拿不到。

处理：如果合并很重要，先把页面调到能完整显示的尺寸（缩小浏览器缩放、拉高窗口），再采。

### 手动采集等待较久时如何判断

先查看状态栏的实际阶段，避免在处理中重复点击下一页：

- 「准备采集」：正在启动或恢复当前任务。首次启动确认额度后开始读页；正常连续采集复用有效授权。网络异常时按提示重试原操作，不重建任务或清空扩展存储。
- 「翻到下一页」：正在执行这张表所属的单次翻页，等待网页响应。
- 「等待网页加载并核对新页」：网页数据、页身份或表头结构尚未确认。等目标表加载，不能仅凭页码变动提前读页。
- 「读取当前页」：正在取本页数据；虚拟表可能自动补滚，先等读取完成。
- 「保存当前页」：正在保存并确认本页结果，暂不翻页。
- 「请翻页」：本页已保存，动画停止，现在可操作网页或点面板「下一页」；正常等待没有固定时限。

若出现失败提示，保留已确认结果，按提示暂停、恢复原任务或导出；不要以连续重复点击、重装或新建任务规避核验。

### 采集到一半页面变了 / 采集中途卡住

- **页面自己刷新或跳转**：采集会中断，并保留已采到的部分。
- **自动采集时滚动或点击**：可能打断插件的滚动、导航；先暂停再操作。手动翻页时按状态提示点击所属分页器，等本页保存后再进入下一页。
- **大表采集很慢**：正常现象，虚拟滚动要逐屏滚动、去重、等 DOM 稳定。可以先小范围试采确认口径。

### 采集按钮点不动 / 面板打不开

| 现象 | 检查 |
|---|---|
| 面板完全不出来 | 扩展是否被浏览器禁用；刷新目标页面重试 |
| 面板出来了但「采集」是灰的 | 还没选中任何表格，或选中的表是 0 行 |
| 图标被隐藏了找不到 | 点浏览器工具栏的扩展图标；或看设置里「隐藏图标时清除本次数据」是否开着 |
| 点图标后反复扫描不打开面板 | 页面没有检测到表格。这是设计行为——检测到才展开 |

## Excel 填充网页

- 翻页结果待核对时，用「核对翻页结果」查询同一次操作，等新表体加载，再按提示确认。
- 一行部分写入时核对当前业务行，必要时重选同一行。整行写完、目标未下移时重选下一业务行，核对映射后继续。
- 网站刷新或原目标无法续接时，核对已写记录，按待填的实际 Excel 行号设置开始行和结束行，再选择网页上的第一条对应业务行。

这一节是反馈最集中的地方。先说清楚一件事：

::: tip 下拉框不是"遇到就跳过"
TableFlow 遇到下拉框会**精确写入**，不是一律跳过。只有四种情况会被拦下：选项集读不全、没有任何选项匹配、匹配到多个、或网页选项集和你 Excel 的不一致。拦下之后怎么处理，由设置里的策略决定（默认是**问你**，不是静默跳过）。
:::

### 插件"明确跳过"了某些字段

**先看这里**：运行页那句提示的完整文案，以及「检查映射」页每个字段的状态列。

"检查映射"这一步每个字段都会标出状态（`可写` / `不填充` / 具体原因）和目标类型，是判断"为什么会跳过"的第一现场：

<figure class="tf-ts">
  <img src="/assets/table-flow/troubleshoot/fill-mapping.webp" alt="检查映射页：每个字段列出地址、当前值、目标类型与可写状态" loading="lazy" />
  <figcaption>检查映射页：每个字段列出地址、当前值、目标类型与可写状态</figcaption>
</figure>

提示里会区分两类跳过，含义完全不同：

| 提示文案 | 真实原因 | 怎么处理 |
|---|---|---|
| 跳过 N 个空字段 | Excel **当前这一行**的该列是空的 | 这不是故障。同一列在有数据的行会正常写入 |
| 按策略跳过 N 个字段（按设置跳过下拉值转文本） | Excel 是下拉列表验证，但网页目标是个普通文本框 | 把「列表填入文本字段时」改成「转换为显示文本」 |
| 按策略跳过 N 个字段（没有能匹配该值的选项） | 严格比对后一个都没匹配上 | 见下方[下拉选项对不上](#下拉选项对不上) |
| 按策略跳过 N 个字段（有多个匹配选项） | 网页里有重复选项 | 无法自动判断，需要手动选 |
| 按策略跳过 N 个字段（无法验证完整选项） | 虚拟滚动/懒加载下拉 | 只能手动填 |

::: warning "这列我明明填了"
「跳过空字段」是**按行**判断的，不是按列。你觉得这列有数据，但当前正在填的那条记录里，这个格子确实是空的。提示里会列出具体是哪个单元格（比如 `B2 数量`），拿它去 Excel 里对一下行号就清楚了。
:::

### 三个设置项决定了填充行为

去 **设置 → 网页填充 → 字段与取值**：

| 设置 | 默认 | 影响什么 |
|---|---|---|
| 检查下拉选项一致性 | 开 | 关闭后不再比对「Excel 列表 vs 网页选项集」 |
| 下拉选项不一致时 | **询问** | 改成「跳过字段」后会静默跳过；改成「停止」则整行不写 |
| 列表填入文本字段时 | **跳过** | 改成「转换为显示文本」才写入文本框 |

**大部分"莫名跳过"都能在这三行找到答案**——尤其是第二行被改成了「跳过字段」的情况，插件只是照配置执行。

### 下拉选项对不上

TableFlow 的比对规则是**严格全等**：

- Excel 里的值和网页选项的显示文本（或选项值）**去掉首尾空格后必须完全一致**；
- 不模糊匹配、不忽略大小写、不做包含判断；
- 必须**恰好命中一个**。

所以最常见的三个原因是：

1. **多了空格**——Excel 里是 `成品仓 `，网页是 `成品仓`。这条最隐蔽。
2. **全角/半角**——`（成品仓）` 和 `(成品仓)` 不是一回事。
3. **网页选项改过名**——以前叫「仓库A」，现在叫「A仓」。

检查方法：在网页上点开那个下拉，把选项文字**复制出来**，和 Excel 单元格做逐字比对。

::: details 为什么不做模糊匹配
因为写错下拉的后果是静默的数据错误。模糊匹配在"看起来差不多"的时候替你做了决定，一旦选错，导出的业务数据是错的，而且事后很难发现。宁可停下来让你确认。
:::

### 「无法验证完整选项」是什么情况

这条提示专指一类下拉：**选项集读不全**。典型特征：

- 下拉是**虚拟滚动**的（几百个选项只渲染十几个）；
- 选项要点开之后才**异步加载**，加载完还有一层延迟;
- 是组件库自己实现的下拉，DOM 上没有标准的 `role="listbox"` / `role="option"` 结构。

插件判断"读不全"时的策略是——**宁可不写，也不猜**。因为无法确认你要的那一项是否真实存在，猜错就是脏数据。

处理办法：这种字段只能手动填。或者在 Excel 里把它改成文本值直接粘贴（前提是网页允许直接输入）。

### 写入后值没变 / 被还原

**先看这里**：运行页提示里有没有「控件拒绝了该值」。

两种不同情况：

**A. 值被控件清洗掉了**
`input[type=number]` 收到 `1,200`、`date` 收到 `2026/10/16` 这类不合规格式时，浏览器会把值**静默置空**——不报错。TableFlow 写入后会回读核对，发现不一致就报「控件拒绝了该值」。
→ 在 Excel 里把格式改成该控件能接受的（纯数字、`2026-10-16`）。

**B. 页面的框架把值改回去了**
React / Vue 这类受控组件会追踪 `value` 的变化。TableFlow 走的是原生 prototype setter 加派发 `input`/`change`/`blur`/`focusout` 事件，就是为了绕过这层追踪。但如果页面有自己的格式化逻辑（比如自动加千分位、自动转大写），会覆盖掉写入的值。
→ 这类页面通常需要手动填，或者先把网页的自动格式化关掉。

### 填完没有自动跳到下一行

**先看这里**：面板提示「网页目标未下移」。

这是**故意拦住**的。原因是：如果网页的目标还停在原来那行，而 Excel 的指针已经前进，下一次填充会把**下一行 Excel 数据覆盖进同一行网页**——错位覆盖，比停下来严重得多。

触发条件：设置里关了「默认填充后自动下移到下一行」，或者页面在填充后重新渲染了那一行（目标不再连续）。

处理：按提示**重新选择下一行**的网页目标，再继续。

### 填了一部分之后失败了

TableFlow 不会留下"写了一半还告诉你成功"的状态。

- **已经写入的字段不回滚**——这是有意的，因为回滚本身也可能失败，反而让现场更难判断；
- **行指针不推进**——修好之后重试，仍然对应同一条业务行，不会错位；
- 面板会逐项列出**哪个字段失败、原因是什么**。

修完直接重试即可，不需要从头再来。

### 撤销按钮点不动

撤销只在一种情况下可用：**刚刚那次填充的目标没有被页面改动过**。

只要页面刷新、切换了目标行、或者那一行的元素被重新渲染，撤销就会失效并提示「字段已变化，无法撤销」——因为此时"恢复原值"这个动作本身没有可靠的目标了。

### 导入 Excel 就失败了

| 提示 | 原因 | 处理 |
|---|---|---|
| 文件格式不支持 | 传了 `.numbers`、`.csv` 或其他非工作簿文件 | 用 Excel 另存为 `.xlsx` |
| 文件里没有可用的工作表 | 只有图表页、隐藏页、宏页 | 切到有数据的普通工作表 |
| 文件已损坏 / 读取失败 | 文件加密、有打开密码、被占用 | 去掉密码、关掉占用它的程序 |
| 解析超时 | 文件过大（几万行以上） | 拆成多个文件分批填 |

::: tip 支持的工作簿
支持 `.xlsx`、`.xls`、`.xlsm`；不执行宏或公式。其他格式请先另存为 Excel 工作簿，并核对日期、前导零和长数字是否已经丢失。
:::

### 选中的起始单元格，和实际填的行对不上

**先看这里**：「设置填充行列」页显示的起始列与起始行。

- **起始行要指向第一条数据**，不是表头行。表头是 `编码/数量/仓库` 在第 1 行，那起始行就填 `2`。
- **有隐藏行时行号会跳**：默认「跳过隐藏行」是关的。开了之后，Excel 里的行号和填充序号会不一致——这是正常的，面板会显示实际用的是哪一行。
- **起始列要指向第一列数据**，不是行号列。

### 映射页显示「不填充」或「未选择」

两种不同的状态，含义完全不同：

| 状态 | 含义 | 怎么改 |
|---|---|---|
| **未选择** | 这一列还没选网页目标 | 回上一步补选 |
| **不填充** | 你主动把它映射成了「无」 | 如果还要填它，重新指定源列 |

「不填充」的字段运行时不写入、也不报「不可写」错误——这是刻意的，避免你被自己关掉的东西反复打扰。

### 提示「网页目标未下移」/ 无法继续

这是**阻断性保护**，不是故障。

如果网页的目标还停在原来那行，而 Excel 指针已经前进，下一次填充会把**下一行 Excel 数据覆盖进同一行网页**——错位覆盖比停下来严重得多。

触发原因：
- 设置里关了「默认填充后自动下移到下一行」；
- 页面在填充后重新渲染了那一行（目标不再连续）；
- 最后一行的下一个 `<tr>` 不存在（表格到底）。

处理：按提示**重新选择下一行**的网页目标，再继续。

### 提示「该控件为只读」/「不支持该控件」

这些提示表示当前控件或状态不满足可验证的写入条件。选目标、预检或实际写入时都可能因页面变化而拒绝。

| 原因 | 典型控件 |
|---|---|
| 只读 | `readonly`、`disabled` 的输入框 |
| 不支持 | 文件上传、单选按钮、混合态复选框、用方块拼的网格、读不全选项的下拉；表单模式仍不支持多选下拉 |
| 该单元格没有可写控件 | 选中的是纯文本单元格，里面没有输入框 |

**能采集不代表能填写**——这是两套独立的判定。遇到这类字段只能在网页上手动填，或者让页面解除只读。

### 填完之后页面自动提交了 / 数据存了两次

既有表格填充不点击提交或保存按钮；逐条新增表单可执行你明确绑定并获准的保存动作。先确认当前填写方式与本批许可。页面也可能因以下行为保存：

1. **页面在 `change` 或 `blur` 时自动保存**——很多后台系统这么做，写入后失焦就触发。这是页面设计，不是插件点击的。
2. **你自己点了提交**，或者按了回车。

输入或失焦本身就可能触发保存；试填前先确认站点规则，需要时联系管理员准备测试记录或关闭自动保存。保存结果未知时先核对业务记录，避免重复提交。

### 部分字段填进去了，部分没有

按顺序排查：

1. **看面板提示**——会逐项列出失败的字段和原因。
2. **看「检查映射」页的状态列**——是不是有字段本来就是「不可写」。
3. **看是不是空字段跳过**——表格填充中，空白或仅空格的来源值会跳过并保留网页旧值，复选框也一样。要取消勾选，请填写明确的 `false`、`0`、`否` 等已配置的取消值。
4. **看下拉选项是否匹配**——严格全等，见[下拉选项对不上](#下拉选项对不上)。

**已写入的字段不会自动回滚，失败记录不推进**。表格填写修正后可重试当前业务行，网页事件可能再次执行；逐条新增若保存结果未知，须先核对保存结果再决定新尝试。

### 填充速度很慢

每个字段写入后要等 DOM 稳定（等框架重渲染、等异步校验），这是必要开销，否则会写进去又被框架还原。

可以加快的：
- 减少单行字段数（只选真正要填的）；
- 关掉「检查下拉选项一致性」（省掉选项集比对）；
- 关掉「默认填充后自动下移到下一行」，改成手动逐行确认（更慢但更可控）。

### 换了一台电脑，之前的模板还能用吗

采集模板与表格填充模板使用浏览器同步存储，能否随账号恢复取决于同步策略；逐条新增表单模板仅存当前机器。清除数据前先备份可导出的配置，不要把同步当作可靠备份。

## 激活、额度与更新

### 续费日期未更新或通知不可用

1. 先确认开发者已处理续费，保留原绑定和付款沟通记录，不重复付款或先卸载。
2. 联网重新进入「账户」等待核验，再核对 Pro 状态与有效期；模板等在线 Pro 入口也可触发核验。原签名日期已过的普通在线码仍按本机强设备身份与实际绑定确认，不能只凭旧签名断网解锁。
3. 出现「待核验」、网络错误或服务异常时检查连接后重试原入口。任务与已采数据保留，不转扣免费；仍失败时向开发者提供设备码、界面提示及处理记录，不提供令牌或恢复秘密。
4. 扩展不申请通知权限、不登记 Push，无需寻找通知开关或等待通知；按第2步核验即可。
5. 离线 Pro 仍以原 TFOL 文件日期为准，续期需重新签发，不靠在线续费延长。

完整流程见[续费步骤](/table-flow/pricing#续费)。账户倒计时只在本地更新，空闲和隐藏页面不循环联网；「最近确认」日期不是待核验时的执行授权。

### 提示需要激活 / Pro 功能点不动

| 现象 | 检查 |
|---|---|
| 显示「免费版（匿名）」 | 当前没有有效 Pro 授权；免费使用不要求登录 TableFlow 账号。打开账户页核对许可证与额度 |
| 显示「Pro（待确认）」 | 激活请求已发出，服务端还没确认。等一会儿刷新，或检查网络 |
| 显示在线权益「待核验」 | 最近确认信息不等于当前权限；联网重新进入账户或使用原 Pro 功能触发复核。失败保留任务，不自动转扣免费 |
| 显示「Pro 已激活（离线授权）」 | 用的是离线激活文件，有效期以文件为准 |
| 换了电脑后变回免费版 | 激活与设备码绑定，换设备需要重新激活或解绑旧设备 |

### 免费额度用完了

先在「账户」查看实际可用次数，不保证固定赠送数量或完成固定次数。新免费翻页采集确认开始扣1次，失败、零结果、结束或清理不退还；同任务继续、切换和输出不再扣费。网页填充翻页共用余额，仍在批次开始扣费。

需要更多额度时联系开发者，由管理员后台直接调整，到账后刷新余额，或购买 Pro；赠额按钮只复核原未到账机会，不支持额度用完后无限新申请。强凭据正常恢复不会再次赠额；全部令牌、恢复材料和服务器域 Cookie 丢失后，账号或指纹不能替代凭据找回旧账本。

### 重装后变成0额度或出现重复领取复核

先在「账户」核对身份和待核验提示。保留强恢复凭据的正常重装沿用原账本；若全部凭据被清除，服务器不能只凭账号或指纹恢复它。配套服务发现历史领取组合证据后，会给新身份0额度并暂缓赠额，旧账本并没有清零。

打开「账户 → 免费额度申请」，点「申请赠额」提交原机会核验，再点「刷新赠额状态」查看；没有原机会时显示实际状态，不会伪造新申请。审批通过与实际到账分别显示。提示配置异常或需要额外额度时联系开发者，由管理员后台处理；不要继续卸载或清 Cookie，也不要把恢复秘密发给别人。详见[免费赠额待核验](/table-flow/pricing#免费赠额待核验)。

### 找不到购买或续费卡片

购买 Pro 从「订阅」使用已有微信 / 支付宝收款码，发送付款截图和在线设备码给开发者，收到激活码后粘贴激活；重复购买和续费表单已移除。续费联系开发者，由管理员后台处理，再到「账户」核对有效期。同一次付款保留原记录等待核验，不重复付款。

离线激活属于付费 Pro，建议先在可联网环境试用目标网页。需要完全断网使用时，在目标设备选择「离线激活」生成离线申请码，联系开发者取得授权文件；在线设备码与离线申请码不能互换。

### 检查更新没反应

点「检查」之后：

- 提示「已是最新」：当前版本就是发布仓里的最新版。
- 提示有新版但下载失败：检查能否访问发布仓（Gitee / GitHub）。
- 完全没反应：核对扩展是否被浏览器禁用。

扩展更新后先刷新已有业务网页，再继续使用；旧版解除 debugger 补丁也需刷新移除。

### Chrome 扩展管理页显示不受信任

「增强型安全浏览功能不信任此扩展程序」属于 Google 的扩展信任判断，与商店审核分开。开发者无法通过 manifest 或更新文档自行去掉提示；Google 未公开 TableFlow 的具体评估原因。核对官方商店来源、扩展 ID 与权限，按浏览器提示决定是否启用；详见[常见问题](/table-flow/faq#chrome-信任提示)。

### 保存结果未知，能直接再点保存吗

逐条新增表单出现保存超时、断连或重启后待核对时，先在业务网站确认该条是否已保存。只有明确未保存且没有在途请求，才为同一记录开始新尝试；不要直接重放。恢复时需重新导入同一文件、确认相同范围与映射并重绑网页目标。

## 需要给开发者反馈时

如果上面都没解决，请按下面的顺序准备。**顺序很重要**——不按这个顺序，导出的文件里没有能定位问题的数据。

### 第一步：先排除"本来就不支持"

花 30 秒看一眼[适用范围与边界](/table-flow/scope)。有一类"故障"其实是明确不支持的能力：

| 你以为的问题 | 实际是 |
|---|---|
| 采不到接口返回的列表 | 数据没渲染成 DOM，本来就不支持 |
| 跨域小窗口里的表不能合并 | 同源策略限制 |
| 列表型表格只采到第一页 | 选择独立「手动翻页采集」，每页核对后接续，见[手动翻页教程](/table-flow/quickstart#手动翻页-按自己的节奏接续) |
| canvas 画的表格采不到 | 本质是图片，读不出文字 |

先排除这些，可以省掉一次往返。

### 第二步：打开调试控制台

去 **设置 → 隐私与诊断 → 调试工具**，打开「采集调试控制台」。

![隐私与诊断页的调试工具开关，默认关闭](/assets/table-flow/troubleshoot/privacy-diagnostics.png)

开启后，采集浮动面板头部会出现「调试」按钮。

::: warning 平时请保持关闭
最小错误诊断在本地内存记录；扩展请求的域名、方法、状态与耗时概览独立保存在 `storage.session`，可跨后台休眠恢复，关闭浏览器会话后清除。调试开关控制额外的页面级探针与取证，不关闭后台这份网络概览；两类记录均不自动上传，调试取证会占用额外性能。
:::

### 解除 debugger 与页面计时器

默认不干预网页计时器；仅打开调试控制台不会自动解除 debugger。

1. 确有需要时，在控制台「…」菜单点「解除 debugger」，阅读中央确认框后手动确认，安全步骤才在当前 frame 启用。
2. 安全步骤只跳过未来新增的纯 debugger 计时回调。普通业务计时器与参数保持原样；混合业务函数、混合业务字符串及无法安全识别的回调也保留，仍可能触发 debugger。
3. 已有计时器不受安全步骤影响。「安全步骤 + 破坏性清扫」需要另行明确选择，会尝试清理已有计时器，也可能影响普通轮询、动画与心跳，不能保证清除全部 debugger；页面异常可刷新恢复。
4. 旧版已在网页运行的补丁不能就地撤销，请刷新旧页面移除，再按需手动启用。关闭调试控制台不会撤销本次补丁。

### 第三步：把出问题的操作再完整做一遍

**这一步不能跳过。**

调试控制台记录的是实际操作。仅打开后立即导出，可能只有既有最小诊断或网络概览，缺少本次失败的页面现场。

1. 保持出问题的页面打开，先保留原任务和已确认结果。
2. 在开启取证后复现相关操作：扫描问题可重新扫描；翻页失败先恢复原任务、核对落页和入口；填充跳过字段则核对原记录和映射，避免重复保存。
3. 看到原提示或失败结果就停手，立即导出。确需新建免费翻页任务时，先核对开始扣1次且不退还的说明，原任务续采不再次扣费。

::: tip 复现时尽量少做无关操作
各类记录均有容量上限，扩展网络概览最多保留最近200条，并按会话存储余量裁剪；反复尝试可能挤掉最早线索。
:::

### 第四步：不要关页面，立刻导出报告

问题刚复现完，**马上**在调试控制台右上角「…」菜单点**导出报告**，得到一个 JSON 文件。

::: danger 这些动作会让部分现场消失
- **后台休眠或重启** → 最小错误诊断内存缓存丢失；会话存储中的扩展网络概览可恢复，不能视为全量现场
- **关闭浏览器** → 会话存储与内存现场清除
- **关掉或刷新出问题的页面** → 当前页面会话与表格现场丢失

所以顺序必须是：**复现 → 立刻导出 → 再慢慢写信**。
:::

::: warning 发送前请自己过一遍
报告里除了运行诊断，还有 DOM 快照、页面信息等其它区块。诊断本身不含你的 Excel 值、网页原值和下拉选项文字，但**其它区块可能有**。发之前打开看一眼，删掉你不希望公开的部分。
:::

### 为什么必须要那份 JSON

你可能会想：我描述得够清楚了，为什么还要折腾导文件？

因为很多问题**光看现象判断不了**。同一个"填充失败"，可能是网页控件只读、可能是下拉没有匹配项、也可能是 Excel 那一格是空的——这三种在面板上可能显示成相近的一句话，但导出文件里记的原因码不同，修法完全不同。**没有那份文件，就只能猜。**

### 什么样的问题描述最有效

| ❌ 效果差 | ✅ 效果好 |
|---|---|
| 「采集不了」 | 「点了采集，面板提示『未检测到表格』，但页面上明明有表格」 |
| 「填充失败」 | 「第 1 行填进去了，第 2 行提示『没有能匹配该值的选项』，仓库列的值是『成品仓』」 |
| 「不好用」 | 「虚拟滚动的大表，采到 994 行但页面显示 1000 行」 |

**关键差别**：有没有说清**面板提示了什么**。面板的提示语都是精心写的，它已经告诉你原因了。

## 手动模式与设置排查

- 一直提示在网页翻页：先确认点击的是目标表所属分页器，等待站点真实数据到位。滚动、排序、旧记录重现、无关联动作不构成新页；无页码虚拟表还需旧页未出现的新记录。
- 列结构变化后暂停：保留并导出已确认数据，重新选择表格和映射后另开任务，不强行沿用旧列顺序。
- 末页少于上一页：网站有下一页禁用等末页证据时可封页；没有总量本身不意味着完整或失败，仍需核对导出记录。
- 填充等待翻页：确认当前页已逐条处理、新页身份与控件可恢复；提前翻页、回退和部分写入会保护性暂停。编辑待填数据后选应用或取消，不能把关闭面板当应用。
- 旧设置路径找不到：九类导航中，「表格采集 → 翻页与等待」是采集延迟/翻页等待上限；「网页填充」分选择与填充、字段与取值；「模板与规则 → 列名规则」管理列表列名。入口位置图见[快速上手](/table-flow/quickstart#新界面里从哪里打开设置)。
- 在线取码、运行续租、执行确认或停止/恢复时提示联网请求超时：在「设置 → 表格采集 → 翻页与等待」调整「联网请求超时」（默认 15 秒，1–120 整数秒），再显式重试原任务；超时不代表未扣次，原待确认请求与已完成数据会保留。该等待与网页加载、激活验证各自独立；在线设备码获取超时也显示此指引，离线申请码在本机生成。网络断开先检查连接，服务或归属拒绝按原错误处理。
