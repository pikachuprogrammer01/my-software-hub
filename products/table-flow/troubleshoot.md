# 排查手册

按**你看到的现象**找条目。每条都给出：先看哪里 → 大概率是什么 → 怎么处理。

::: tip 排查前先做这一件事
刷新目标网页后重新扫描一次。页面改版、前端热更新、切过标签页之后，插件记住的表格引用可能已经失效——这类"假故障"占了相当一部分反馈。
:::

## 先定位：问题属于哪一段

TableFlow 有两条方向相反的工作流，故障现象相似但原因完全不同：

| 你在做什么 | 走哪条链路 | 本文位置 |
|---|---|---|
| 把网页上的表格**采下来**导出 | 扫描 → 选择 → 采集 → 导出 | [采集与导出](#采集与导出) |
| 把本地 Excel 的**行写进网页** | 导入 → 选目标 → 检查映射 → 逐行填充 | [Excel 填充网页](#excel-填充网页) |

判断依据很简单：**面板里选的是「采集网页数据」还是「Excel 填充网页」**。选错了模式，后面的操作都不会有反应。

## 采集与导出

### 面板显示「未检测到表格」

**先看这里**：面板空状态提示，以及页面上的表格是不是真的"画"出来了。

按可能性排序：

1. **表格还没渲染完**——页面提示「内容可能未完全加载」时，等页面稳定后点「重新扫描」。
2. **表格在折叠面板里**——先手动展开那一块，再扫描。
3. **表格是 `ul`/`li` 列表**——去设置里确认「列表识别（ul/li）」已开启；如果开了还是识别成奇怪的样子，把「列表识别严格度」从「标准」放宽到「宽松」再重扫。
4. **数据只在接口里、没画到页面上**——这种采不到，属于[已知边界](/table-flow/scope)。插件读的是浏览器渲染出来的 DOM，读不到网络请求里还没上屏的数据。
5. **表格在别人的网站的小窗口里（跨域 iframe）**——默认只放行政务类域名。其他站点要在设置里把「扫描所有跨域 iframe」打开，或手动把域名加进白名单。

::: warning 跨域小窗口的额外限制
跨域 iframe 里的表**不参与合并**，也不能和其他表拼成一份导出。这是浏览器的同源策略决定的，不是设置问题。
:::

### 表格识别出来了，但只有一部分行

**先看这里**：导出后的总行数，对比页面上"共 N 条"的提示。

最典型的原因是**虚拟滚动**——长列表只渲染看得见的那几行。TableFlow 会自己滚动逐屏抓取去重，但有两个前提：

- 自动翻页**关着也能**采全当前页（靠自动滚动）；
- 需要滚动才能出现的行，采集过程中**不要动鼠标滚轮**，否则会和插件的滚动打架。

如果行数对不上，用「重新扫描」后重采一次；仍然缺行，把页面滚到底再扫描，让浏览器把内容渲染出来。

### 翻页没有反应 / 翻到一半停了

**先看这里**：采集结束时的提示语。它会明说停在哪、为什么停，不会假装采全了。

| 提示 | 含义 | 处理 |
|---|---|---|
| 达到最大页数 | 默认上限见下方说明，**从你开始的那一页起算** | 设置里调大「自动翻页默认最大页数」，或分段采集 |
| 检测到页面没有变化 | 页码变了但内容没变（"错联分页器"） | 换「手动拾取」指定真正的下一页按钮 |
| 无法确认是否已到最后一页 | 判断不了就停下来问你，而不是悄悄漏采 | 确认页面确实到底后，手动结束 |
| 加载更多达到轮数上限 | 无限滚动类入口有独立轮数预算，触顶可续采 | 再次点采集继续 |

**下一页按钮不是标准写法时**：用面板上的「手动拾取翻页入口」——鼠标悬停会高亮，点一下确认。跨域小窗口里也能用（父页面投递、子窗口内拾取），30 秒无操作会自动停止。

### 导出失败或文件是空的

按顺序检查：

1. **有没有先采集**——导出的是「采集结果」，只扫描不采集时列表是空的。
2. **免费版的单次行数上限**——超限时面板会提示，导出会被截断或拒绝。
3. **下载被浏览器拦了**——地址栏右侧如果有被拦截的下载图标，点开允许 `chrome-extension://` 来源的下载。
4. **文件名里有非法字符**——自定义文件名不要带 `/ \ : * ? " < > |`。

## Excel 填充网页

这一节是反馈最集中的地方。先说清楚一件事：

::: tip 下拉框不是"遇到就跳过"
TableFlow 遇到下拉框会**精确写入**，不是一律跳过。只有四种情况会被拦下：选项集读不全、没有任何选项匹配、匹配到多个、或网页选项集和你 Excel 的不一致。拦下之后怎么处理，由设置里的策略决定（默认是**问你**，不是静默跳过）。
:::

### 插件"明确跳过"了某些字段

**先看这里**：运行页那句提示的完整文案，以及「检查映射」页每个字段的状态列。

"检查映射"这一步每个字段都会标出状态（`可写` / `不填充` / 具体原因）和目标类型，是判断"为什么会跳过"的第一现场：

<figure class="tf-ts">
  <img src="/assets/table-flow/troubleshoot/fill-mapping.webp" alt="检查映射页：每个字段列出地址、当前值、目标类型与可写状态" loading="lazy" />
  <figcaption>检查映射页：每个字段列出地址、当前值、目标类型与可写状态</figcaption>
</figure>

提示里会区分两类跳过，含义完全不同：

| 提示文案 | 真实原因 | 怎么处理 |
|---|---|---|
| 跳过 N 个空字段 | Excel **当前这一行**的该列是空的 | 这不是故障。同一列在有数据的行会正常写入 |
| 按策略跳过 N 个字段（按设置跳过下拉值转文本） | Excel 是下拉列表验证，但网页目标是个普通文本框 | 把「列表填入文本字段时」改成「转换为显示文本」 |
| 按策略跳过 N 个字段（没有能匹配该值的选项） | 严格比对后一个都没匹配上 | 见下方[下拉选项对不上](#下拉选项对不上) |
| 按策略跳过 N 个字段（有多个匹配选项） | 网页里有重复选项 | 无法自动判断，需要手动选 |
| 按策略跳过 N 个字段（无法验证完整选项） | 虚拟滚动/懒加载下拉 | 只能手动填 |

::: warning "这列我明明填了"
「跳过空字段」是**按行**判断的，不是按列。你觉得这列有数据，但当前正在填的那条记录里，这个格子确实是空的。提示里会列出具体是哪个单元格（比如 `B2 数量`），拿它去 Excel 里对一下行号就清楚了。
:::

### 三个设置项决定了填充行为

去 **设置 → 数据设置 → Excel 网页填充**：

<figure class="tf-ts">
  <img src="/assets/table-flow/troubleshoot/web-fill-settings.webp" alt="设置 → 数据设置 → Excel 网页填充，最后三行决定了下拉框怎么处理" loading="lazy" />
  <figcaption>设置 → 数据设置 → Excel 网页填充，最后三行决定了下拉框怎么处理</figcaption>
</figure>

| 设置 | 默认 | 影响什么 |
|---|---|---|
| 检查下拉选项一致性 | 开 | 关闭后不再比对「Excel 列表 vs 网页选项集」 |
| 下拉选项不一致时 | **询问** | 改成「跳过字段」后会静默跳过；改成「停止」则整行不写 |
| 列表填入文本字段时 | **跳过** | 改成「转换为显示文本」才写入文本框 |

**大部分"莫名跳过"都能在这三行找到答案**——尤其是第二行被改成了「跳过字段」的情况，插件只是照配置执行。

### 下拉选项对不上

TableFlow 的比对规则是**严格全等**：

- Excel 里的值和网页选项的显示文本（或选项值）**去掉首尾空格后必须完全一致**；
- 不模糊匹配、不忽略大小写、不做包含判断；
- 必须**恰好命中一个**。

所以最常见的三个原因是：

1. **多了空格**——Excel 里是 `成品仓 `，网页是 `成品仓`。这条最隐蔽。
2. **全角/半角**——`（成品仓）` 和 `(成品仓)` 不是一回事。
3. **网页选项改过名**——以前叫「仓库A」，现在叫「A仓」。

检查方法：在网页上点开那个下拉，把选项文字**复制出来**，和 Excel 单元格做逐字比对。

::: details 为什么不做模糊匹配
因为写错下拉的后果是静默的数据错误。模糊匹配在"看起来差不多"的时候替你做了决定，一旦选错，导出的业务数据是错的，而且事后很难发现。宁可停下来让你确认。
:::

### 「无法验证完整选项」是什么情况

这条提示专指一类下拉：**选项集读不全**。典型特征：

- 下拉是**虚拟滚动**的（几百个选项只渲染十几个）；
- 选项要点开之后才**异步加载**，加载完还有一层延迟;
- 是组件库自己实现的下拉，DOM 上没有标准的 `role="listbox"` / `role="option"` 结构。

插件判断"读不全"时的策略是——**宁可不写，也不猜**。因为无法确认你要的那一项是否真实存在，猜错就是脏数据。

处理办法：这种字段只能手动填。或者在 Excel 里把它改成文本值直接粘贴（前提是网页允许直接输入）。

### 写入后值没变 / 被还原

**先看这里**：运行页提示里有没有「控件拒绝了该值」。

两种不同情况：

**A. 值被控件清洗掉了**
`input[type=number]` 收到 `1,200`、`date` 收到 `2026/10/16` 这类不合规格式时，浏览器会把值**静默置空**——不报错。TableFlow 写入后会回读核对，发现不一致就报「控件拒绝了该值」。
→ 在 Excel 里把格式改成该控件能接受的（纯数字、`2026-10-16`）。

**B. 页面的框架把值改回去了**
React / Vue 这类受控组件会追踪 `value` 的变化。TableFlow 走的是原生 prototype setter 加派发 `input`/`change`/`blur`/`focusout` 事件，就是为了绕过这层追踪。但如果页面有自己的格式化逻辑（比如自动加千分位、自动转大写），会覆盖掉写入的值。
→ 这类页面通常需要手动填，或者先把网页的自动格式化关掉。

### 填完没有自动跳到下一行

**先看这里**：面板提示「网页目标未下移」。

这是**故意拦住**的。原因是：如果网页的目标还停在原来那行，而 Excel 的指针已经前进，下一次填充会把**下一行 Excel 数据覆盖进同一行网页**——错位覆盖，比停下来严重得多。

触发条件：设置里关了「默认填充后自动下移到下一行」，或者页面在填充后重新渲染了那一行（目标不再连续）。

处理：按提示**重新选择下一行**的网页目标，再继续。

### 填了一部分之后失败了

TableFlow 不会留下"写了一半还告诉你成功"的状态。

- **已经写入的字段不回滚**——这是有意的，因为回滚本身也可能失败，反而让现场更难判断；
- **行指针不推进**——修好之后重试，仍然对应同一条业务行，不会错位；
- 面板会逐项列出**哪个字段失败、原因是什么**。

修完直接重试即可，不需要从头再来。

### 撤销按钮点不动

撤销只在一种情况下可用：**刚刚那次填充的目标没有被页面改动过**。

只要页面刷新、切换了目标行、或者那一行的元素被重新渲染，撤销就会失效并提示「字段已变化，无法撤销」——因为此时"恢复原值"这个动作本身没有可靠的目标了。

## 激活、额度与更新

### 提示需要激活 / Pro 功能点不动

| 现象 | 检查 |
|---|---|
| 显示「免费版（匿名）」 | 扩展没登录到账号。重新打开扩展的账户页 |
| 显示「Pro（待确认）」 | 激活请求已发出，服务端还没确认。等一会儿刷新，或检查网络 |
| 显示「Pro 已激活（离线授权）」 | 用的是离线激活文件，有效期以文件为准 |
| 换了电脑后变回免费版 | 激活和设备的指纹绑定，换设备需要重新激活或解绑旧设备 |

### 免费额度用完了

免费版有单次**行数**与**翻页次数**的上限，Pro 没有。看面板上的额度提示，它会说明是哪一个先到顶。

### 检查更新没反应

点「检查」之后：

- 提示「已是最新」= 当前版本就是发布仓里的最新版；
- 提示有新版但下载失败 = 检查能否访问发布仓（Gitee / GitHub）；
- 完全没反应 = 看一眼扩展有没有被浏览器禁用。

## 需要给开发者反馈时

如果上面都没解决，按这个顺序收集信息，能大幅缩短定位时间。

### 第一步：打开调试控制台

去 **设置 → 隐私与诊断 → 调试工具**，打开「采集调试控制台」。

<figure class="tf-ts">
  <img src="/assets/table-flow/troubleshoot/privacy-diagnostics.webp" alt="隐私与诊断页的调试工具开关，默认关闭" loading="lazy" />
  <figcaption>隐私与诊断页的调试工具开关，默认关闭</figcaption>
</figure>

开启后，采集浮动面板头部会出现「调试」按钮。

::: warning 平时请保持关闭
调试模式会额外记录运行诊断，还会启用页面级探针。它只在本地内存里存（关闭浏览器即丢弃），不发送到任何地方，但会占用一点性能。
:::

### 第二步：切到「填充」页签

点「刷新状态」读当前填充状态；下面是最近 100 条填充事件。

每条事件只记**计数和原因码**——不含你的 Excel 值、网页原值、也不含下拉选项文字。所以可以直接发出来。

事件按阶段记录，看 `precheck` 这一条最关键：

| 阶段 | 说明什么 |
|---|---|
| `selection` | 选目标的结果 |
| `preparation` | 准备阶段（页面跳转后重建目标） |
| `precheck` | **预检**：拦下了几个字段、原因码是什么、有没有进确认 |
| `confirmation` | 确认面板的待定项 |
| `write` | 逐字段写入的成功/失败 |
| `advance` | 自动下移是否成功、被什么拦住 |
| `undo` | 撤销结果 |

`precheck` 显示 `blocked` 就说明**根本没进写入**；显示 `ready` 然后 `write` 失败，就是写入环节的问题。

### 第三步：导出报告

调试控制台右上角「…」菜单 → **导出报告**，得到一个 JSON 文件。

::: danger 发送前请自己过一遍
报告里除了填充诊断，还有 DOM 快照、页面信息等其它区块。填充诊断本身不含隐私数据，但**其它区块可能有**。发之前打开看一眼，删掉你不希望公开的部分。
:::

### 反馈时请一并说明

1. 目标网页的**类型**（政府公告 / 内部系统 / 电商后台…）——不用给具体网址；
2. 卡在哪一步（选择表格 / 设置行列 / 检查映射 / 逐行填充）；
3. 面板提示的**完整文案**（截图最好）；
4. 上面导出的报告 JSON。
