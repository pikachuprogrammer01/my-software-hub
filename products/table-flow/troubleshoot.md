# 排查手册

按**你看到的现象**找条目。每条都给出：先看哪里 → 大概率是什么 → 怎么处理。

::: tip 排查前先做这一件事
刷新目标网页后重新扫描一次。页面改版、前端热更新、切过标签页之后，插件记住的表格引用可能已经失效——这类"假故障"占了相当一部分反馈。
:::

## 先定位：问题属于哪一段

TableFlow 有两条方向相反的工作流，故障现象相似但原因完全不同：

| 你在做什么 | 走哪条链路 | 本文位置 |
|---|---|---|
| 把网页上的表格**采下来**导出 | 扫描 → 选择 → 采集 → 导出 | [采集与导出](#采集与导出) |
| 把本地 Excel 的**行写进网页** | 导入 → 选目标 → 检查映射 → 逐行填充 | [Excel 填充网页](#excel-填充网页) |

判断依据很简单：**面板里选的是「采集网页数据」还是「Excel 填充网页」**。选错了模式，后面的操作都不会有反应。

## 采集与导出

### 面板显示「未检测到表格」

**先看这里**：面板空状态提示，以及页面上的表格是不是真的"画"出来了。

按可能性排序：

1. **表格还没渲染完**——页面提示「内容可能未完全加载」时，等页面稳定后点「重新扫描」。
2. **表格在折叠面板里**——先手动展开那一块，再扫描。
3. **表格是 `ul`/`li` 列表**——去设置里确认「列表识别（ul/li）」已开启；如果开了还是识别成奇怪的样子，把「列表识别严格度」从「标准」放宽到「宽松」再重扫。
4. **数据只在接口里、没画到页面上**——这种采不到，属于[已知边界](/table-flow/scope)。插件读的是浏览器渲染出来的 DOM，读不到网络请求里还没上屏的数据。
5. **表格在别人的网站的小窗口里（跨域 iframe）**——默认只放行政务类域名。其他站点要在设置里把「扫描所有跨域 iframe」打开，或手动把域名加进白名单。

::: warning 跨域小窗口的额外限制
跨域 iframe 里的表**不参与合并**，也不能和其他表拼成一份导出。这是浏览器的同源策略决定的，不是设置问题。
:::

### 表格识别出来了，但只有一部分行

**先看这里**：导出后的总行数，对比页面上"共 N 条"的提示。

最典型的原因是**虚拟滚动**——长列表只渲染看得见的那几行。TableFlow 会自己滚动逐屏抓取去重，但有两个前提：

- 自动翻页**关着也能**采全当前页（靠自动滚动）；
- 需要滚动才能出现的行，采集过程中**不要动鼠标滚轮**，否则会和插件的滚动打架。

如果行数对不上，用「重新扫描」后重采一次；仍然缺行，把页面滚到底再扫描，让浏览器把内容渲染出来。

### 翻页没有反应 / 翻到一半停了

**先看这里**：采集结束时的提示语。它会明说停在哪、为什么停，不会假装采全了。

| 提示 | 含义 | 处理 |
|---|---|---|
| 达到最大页数 | 默认上限见下方说明，**从你开始的那一页起算** | 设置里调大「自动翻页默认最大页数」，或分段采集 |
| 检测到页面没有变化 | 页码变了但内容没变（"错联分页器"） | 换「手动拾取」指定真正的下一页按钮 |
| 无法确认是否已到最后一页 | 判断不了就停下来问你，而不是悄悄漏采 | 确认页面确实到底后，手动结束 |
| 加载更多达到轮数上限 | 无限滚动类入口有独立轮数预算，触顶可续采 | 再次点采集继续 |

**下一页按钮不是标准写法时**：用面板上的「手动拾取翻页入口」——鼠标悬停会高亮，点一下确认。跨域小窗口里也能用（父页面投递、子窗口内拾取），30 秒无操作会自动停止。

### 导出失败或文件是空的

按顺序检查：

1. **有没有先采集**——导出的是「采集结果」，只扫描不采集时列表是空的。
2. **免费版的单次行数上限**——超限时面板会提示，导出会被截断或拒绝。
3. **下载被浏览器拦了**——地址栏右侧如果有被拦截的下载图标，点开允许 `chrome-extension://` 来源的下载。
4. **文件名里有非法字符**——自定义文件名不要带 `/ \ : * ? " < > |`。

---

### 列名乱了 / 列名变成「列1」「列2」

**先看这里**：导出文件里的表头行。

原因分三种：

1. **列表型表格（`ul`/`li`）没有列名声明**——这类结构本身不带表头。去 **设置 → 数据设置 → 列名规则** 加一条规则：选「日期」「标题链接」这类现成选项，填个你想要的列名，重扫后就按你的名字显示。
2. **表头行被当成了数据行**——合并单元格、两行表头、表头里有输入框的复杂表格容易这样。检查导出的第一行是不是被当成了数据。
3. **多级表头只保留了末级**——多级表头会拼成 `上级 > 子级` 的形式。如果你想看层级关系，看导出文件的完整表头；如果显示成单级，说明那一层没有识别到合并信息。

### 采集出来的数字变成了科学计数法（1.23E+15）

**这是 Excel 的显示行为，不是数据错了。**

订单号、身份证号、长编号这类超过 15 位的数字，Excel 会按数值处理并显示成科学计数法，**而且第 16 位之后会被抹成 0**。这是 Excel 的精度限制（IEEE 754 双精度），任何工具导出的 CSV 用 Excel 打开都会这样。

三种处理方式：

| 做法 | 效果 |
|---|---|
| 导出成 **CSV** 后用「数据 → 从文本/CSV」导入，把该列设为**文本** | 完全保真，推荐 |
| 导出成 **JSON** | 保真，但需要再转换 |
| 导出前把该列识别为文本（Excel 里提前把列格式设为文本） | 保真，但要求导出环节保留文本类型 |

::: warning 直接双击打开 CSV 一定会这样
这不是 TableFlow 能控制的——是 Excel 打开 CSV 时的默认类型推断。要用 CSV + Excel，请走「导入」流程而不是双击。
:::

### 采集结果有重复行

**先看这里**：面板上的去重开关，以及重复行是否「完全一样」。

- **完全相同的行**：去重功能没开。采集结果页有去重入口。
- **看起来一样但有细微差别**（多一个空格、全半角不同）：去重按严格比对，这类不会合并。导出后自己处理。
- **分页采集时重复**：翻页边界重复读到同一页。TableFlow 会用「行身份」判断是不是同一行——优先用 `data-id` 这类行 ID，没有就用「位置 + 文字」。如果页面每次渲染都改 ID，可能判不出来。

### 只采到了当前这一页

先确认自动翻页有没有开，再确认「翻页入口」有没有识别到：

- **下一页按钮不是标准写法**（图标按钮、无文字、自定义组件）→ 用「手动拾取翻页入口」。
- **表格在跨域小窗口里** → 可以在帧内手动点选翻页按钮，但**帧内的表不参与合并**。
- **Load More / 无限滚动** → 按新增行数推进，轮数有独立预算（单次默认 200 轮），触顶可续采。
- **列表型表格（`ul`/`li`）** → **只采当前页**，列表的翻页尚未支持。这是当前的能力边界。

### 合并单元格的样式丢了

合并信息按「采集那一刻的渲染状态」记录。如果是虚拟滚动表格，**已经滚出窗口的合并可能补不全**——这是已知限制，因为滚出视口后 DOM 已经被回收，合并信息拿不到。

处理：如果合并很重要，先把页面调到能完整显示的尺寸（缩小浏览器缩放、拉高窗口），再采。

### 采集到一半页面变了 / 采集中途卡住

- **页面自己刷新或跳转**：采集会中断，并保留已采到的部分。
- **采集中你手动滚动或点击**：会和插件的滚动、翻页操作打架。采集期间尽量别动页面。
- **大表采集很慢**：正常现象，虚拟滚动要逐屏滚动、去重、等 DOM 稳定。可以先小范围试采确认口径。

### 采集按钮点不动 / 面板打不开

| 现象 | 检查 |
|---|---|
| 面板完全不出来 | 扩展是否被浏览器禁用；刷新目标页面重试 |
| 面板出来了但「采集」是灰的 | 还没选中任何表格，或选中的表是 0 行 |
| 图标被隐藏了找不到 | 点浏览器工具栏的扩展图标；或看设置里「隐藏图标时清除本次数据」是否开着 |
| 点图标后反复扫描不打开面板 | 页面没有检测到表格。这是设计行为——检测到才展开 |

## Excel 填充网页

这一节是反馈最集中的地方。先说清楚一件事：

::: tip 下拉框不是"遇到就跳过"
TableFlow 遇到下拉框会**精确写入**，不是一律跳过。只有四种情况会被拦下：选项集读不全、没有任何选项匹配、匹配到多个、或网页选项集和你 Excel 的不一致。拦下之后怎么处理，由设置里的策略决定（默认是**问你**，不是静默跳过）。
:::

### 插件"明确跳过"了某些字段

**先看这里**：运行页那句提示的完整文案，以及「检查映射」页每个字段的状态列。

"检查映射"这一步每个字段都会标出状态（`可写` / `不填充` / 具体原因）和目标类型，是判断"为什么会跳过"的第一现场：

<figure class="tf-ts">
  <img src="/assets/table-flow/troubleshoot/fill-mapping.webp" alt="检查映射页：每个字段列出地址、当前值、目标类型与可写状态" loading="lazy" />
  <figcaption>检查映射页：每个字段列出地址、当前值、目标类型与可写状态</figcaption>
</figure>

提示里会区分两类跳过，含义完全不同：

| 提示文案 | 真实原因 | 怎么处理 |
|---|---|---|
| 跳过 N 个空字段 | Excel **当前这一行**的该列是空的 | 这不是故障。同一列在有数据的行会正常写入 |
| 按策略跳过 N 个字段（按设置跳过下拉值转文本） | Excel 是下拉列表验证，但网页目标是个普通文本框 | 把「列表填入文本字段时」改成「转换为显示文本」 |
| 按策略跳过 N 个字段（没有能匹配该值的选项） | 严格比对后一个都没匹配上 | 见下方[下拉选项对不上](#下拉选项对不上) |
| 按策略跳过 N 个字段（有多个匹配选项） | 网页里有重复选项 | 无法自动判断，需要手动选 |
| 按策略跳过 N 个字段（无法验证完整选项） | 虚拟滚动/懒加载下拉 | 只能手动填 |

::: warning "这列我明明填了"
「跳过空字段」是**按行**判断的，不是按列。你觉得这列有数据，但当前正在填的那条记录里，这个格子确实是空的。提示里会列出具体是哪个单元格（比如 `B2 数量`），拿它去 Excel 里对一下行号就清楚了。
:::

### 三个设置项决定了填充行为

去 **设置 → 数据设置 → Excel 网页填充**：

<figure class="tf-ts">
  <img src="/assets/table-flow/troubleshoot/web-fill-settings.webp" alt="设置 → 数据设置 → Excel 网页填充，最后三行决定了下拉框怎么处理" loading="lazy" />
  <figcaption>设置 → 数据设置 → Excel 网页填充，最后三行决定了下拉框怎么处理</figcaption>
</figure>

| 设置 | 默认 | 影响什么 |
|---|---|---|
| 检查下拉选项一致性 | 开 | 关闭后不再比对「Excel 列表 vs 网页选项集」 |
| 下拉选项不一致时 | **询问** | 改成「跳过字段」后会静默跳过；改成「停止」则整行不写 |
| 列表填入文本字段时 | **跳过** | 改成「转换为显示文本」才写入文本框 |

**大部分"莫名跳过"都能在这三行找到答案**——尤其是第二行被改成了「跳过字段」的情况，插件只是照配置执行。

### 下拉选项对不上

TableFlow 的比对规则是**严格全等**：

- Excel 里的值和网页选项的显示文本（或选项值）**去掉首尾空格后必须完全一致**；
- 不模糊匹配、不忽略大小写、不做包含判断；
- 必须**恰好命中一个**。

所以最常见的三个原因是：

1. **多了空格**——Excel 里是 `成品仓 `，网页是 `成品仓`。这条最隐蔽。
2. **全角/半角**——`（成品仓）` 和 `(成品仓)` 不是一回事。
3. **网页选项改过名**——以前叫「仓库A」，现在叫「A仓」。

检查方法：在网页上点开那个下拉，把选项文字**复制出来**，和 Excel 单元格做逐字比对。

::: details 为什么不做模糊匹配
因为写错下拉的后果是静默的数据错误。模糊匹配在"看起来差不多"的时候替你做了决定，一旦选错，导出的业务数据是错的，而且事后很难发现。宁可停下来让你确认。
:::

### 「无法验证完整选项」是什么情况

这条提示专指一类下拉：**选项集读不全**。典型特征：

- 下拉是**虚拟滚动**的（几百个选项只渲染十几个）；
- 选项要点开之后才**异步加载**，加载完还有一层延迟;
- 是组件库自己实现的下拉，DOM 上没有标准的 `role="listbox"` / `role="option"` 结构。

插件判断"读不全"时的策略是——**宁可不写，也不猜**。因为无法确认你要的那一项是否真实存在，猜错就是脏数据。

处理办法：这种字段只能手动填。或者在 Excel 里把它改成文本值直接粘贴（前提是网页允许直接输入）。

### 写入后值没变 / 被还原

**先看这里**：运行页提示里有没有「控件拒绝了该值」。

两种不同情况：

**A. 值被控件清洗掉了**
`input[type=number]` 收到 `1,200`、`date` 收到 `2026/10/16` 这类不合规格式时，浏览器会把值**静默置空**——不报错。TableFlow 写入后会回读核对，发现不一致就报「控件拒绝了该值」。
→ 在 Excel 里把格式改成该控件能接受的（纯数字、`2026-10-16`）。

**B. 页面的框架把值改回去了**
React / Vue 这类受控组件会追踪 `value` 的变化。TableFlow 走的是原生 prototype setter 加派发 `input`/`change`/`blur`/`focusout` 事件，就是为了绕过这层追踪。但如果页面有自己的格式化逻辑（比如自动加千分位、自动转大写），会覆盖掉写入的值。
→ 这类页面通常需要手动填，或者先把网页的自动格式化关掉。

### 填完没有自动跳到下一行

**先看这里**：面板提示「网页目标未下移」。

这是**故意拦住**的。原因是：如果网页的目标还停在原来那行，而 Excel 的指针已经前进，下一次填充会把**下一行 Excel 数据覆盖进同一行网页**——错位覆盖，比停下来严重得多。

触发条件：设置里关了「默认填充后自动下移到下一行」，或者页面在填充后重新渲染了那一行（目标不再连续）。

处理：按提示**重新选择下一行**的网页目标，再继续。

### 填了一部分之后失败了

TableFlow 不会留下"写了一半还告诉你成功"的状态。

- **已经写入的字段不回滚**——这是有意的，因为回滚本身也可能失败，反而让现场更难判断；
- **行指针不推进**——修好之后重试，仍然对应同一条业务行，不会错位；
- 面板会逐项列出**哪个字段失败、原因是什么**。

修完直接重试即可，不需要从头再来。

### 撤销按钮点不动

撤销只在一种情况下可用：**刚刚那次填充的目标没有被页面改动过**。

只要页面刷新、切换了目标行、或者那一行的元素被重新渲染，撤销就会失效并提示「字段已变化，无法撤销」——因为此时"恢复原值"这个动作本身没有可靠的目标了。

### 导入 Excel 就失败了

| 提示 | 原因 | 处理 |
|---|---|---|
| 文件格式不支持 | 传了 `.xls`（旧格式）、`.numbers`、`.csv` | 用 Excel 另存为 `.xlsx` |
| 文件里没有可用的工作表 | 只有图表页、隐藏页、宏页 | 切到有数据的普通工作表 |
| 文件已损坏 / 读取失败 | 文件加密、有打开密码、被占用 | 去掉密码、关掉占用它的程序 |
| 解析超时 | 文件过大（几万行以上） | 拆成多个文件分批填 |

::: tip 只支持 .xlsx
旧版 `.xls` 和 `.csv` 请先用 Excel 另存为 `.xlsx`。这是有意的——`.csv` 没有类型信息，日期、前导零、长数字都可能在保存时就已经丢失精度。
:::

### 选中的起始单元格，和实际填的行对不上

**先看这里**：「设置填充行列」页显示的起始列与起始行。

- **起始行要指向第一条数据**，不是表头行。表头是 `编码/数量/仓库` 在第 1 行，那起始行就填 `2`。
- **有隐藏行时行号会跳**：默认「跳过隐藏行」是关的。开了之后，Excel 里的行号和填充序号会不一致——这是正常的，面板会显示实际用的是哪一行。
- **起始列要指向第一列数据**，不是行号列。

### 映射页显示「不填充」或「未选择」

两种不同的状态，含义完全不同：

| 状态 | 含义 | 怎么改 |
|---|---|---|
| **未选择** | 这一列还没选网页目标 | 回上一步补选 |
| **不填充** | 你主动把它映射成了「无」 | 如果还要填它，重新指定源列 |

「不填充」的字段运行时不写入、也不报「不可写」错误——这是刻意的，避免你被自己关掉的东西反复打扰。

### 提示「网页目标未下移」/ 无法继续

这是**阻断性保护**，不是故障。

如果网页的目标还停在原来那行，而 Excel 指针已经前进，下一次填充会把**下一行 Excel 数据覆盖进同一行网页**——错位覆盖比停下来严重得多。

触发原因：
- 设置里关了「默认填充后自动下移到下一行」；
- 页面在填充后重新渲染了那一行（目标不再连续）；
- 最后一行的下一个 `<tr>` 不存在（表格到底）。

处理：按提示**重新选择下一行**的网页目标，再继续。

### 提示「该控件为只读」/「首版不支持该控件」

**这一类不是跳过，是选目标那一刻就判定不可写。**

| 原因 | 典型控件 |
|---|---|
| 只读 | `readonly`、`disabled` 的输入框 |
| 首版不支持 | 文件上传、勾选框、单选按钮、用方块拼的网格、读不全选项的下拉 |
| 该单元格没有可写控件 | 选中的是纯文本单元格，里面没有输入框 |

**能采集不代表能填写**——这是两套独立的判定。遇到这类字段只能在网页上手动填，或者让页面解除只读。

### 填完之后页面自动提交了 / 数据存了两次

TableFlow **不会点击任何提交或保存按钮**。如果页面自己提交了，通常是这两种情况：

1. **页面在 `change` 或 `blur` 时自动保存**——很多后台系统这么做，写入后失焦就触发。这是页面设计，不是插件点击的。
2. **你自己点了提交**，或者按了回车。

如果需要避免自动保存：先填完一行、确认没问题再离开那个输入框；或联系页面管理员关闭自动保存。

### 部分字段填进去了，部分没有

按顺序排查：

1. **看面板提示**——会逐项列出失败的字段和原因。
2. **看「检查映射」页的状态列**——是不是有字段本来就是「不可写」。
3. **看是不是空字段跳过**——Excel 当前行该列为空，不写、保留网页原值。
4. **看下拉选项是否匹配**——严格全等，见[下拉选项对不上](#下拉选项对不上)。

**已写入的字段不会回滚，行指针也不推进**——修好直接重试即可，仍对应同一条业务行。

### 填充速度很慢

每个字段写入后要等 DOM 稳定（等框架重渲染、等异步校验），这是必要开销，否则会写进去又被框架还原。

可以加快的：
- 减少单行字段数（只选真正要填的）；
- 关掉「检查下拉选项一致性」（省掉选项集比对）；
- 关掉「默认填充后自动下移到下一行」，改成手动逐行确认（更慢但更可控）。

### 换了一台电脑，之前的模板还能用吗

模板保存在**当前浏览器**里。换电脑、重装浏览器、清空扩展数据，模板都会丢。

Pro 的「模板」功能可以导出/导入模板配置——建议换设备前先导出。

## 激活、额度与更新

### 提示需要激活 / Pro 功能点不动

| 现象 | 检查 |
|---|---|
| 显示「免费版（匿名）」 | 扩展没登录到账号。重新打开扩展的账户页 |
| 显示「Pro（待确认）」 | 激活请求已发出，服务端还没确认。等一会儿刷新，或检查网络 |
| 显示「Pro 已激活（离线授权）」 | 用的是离线激活文件，有效期以文件为准 |
| 换了电脑后变回免费版 | 激活和设备的指纹绑定，换设备需要重新激活或解绑旧设备 |

### 免费额度用完了

免费版有单次**行数**与**翻页次数**的上限，Pro 没有。看面板上的额度提示，它会说明是哪一个先到顶。

### 检查更新没反应

点「检查」之后：

- 提示「已是最新」= 当前版本就是发布仓里的最新版；
- 提示有新版但下载失败 = 检查能否访问发布仓（Gitee / GitHub）；
- 完全没反应 = 看一眼扩展有没有被浏览器禁用。

## 需要给开发者反馈时

如果上面都没解决，请按下面的顺序准备。**顺序很重要**——不按这个顺序，导出的文件里没有能定位问题的数据。

### 第一步：先排除"本来就不支持"

花 30 秒看一眼[适用范围与边界](/table-flow/scope)。有一类"故障"其实是明确不支持的能力：

| 你以为的问题 | 实际是 |
|---|---|
| 采不到接口返回的列表 | 数据没渲染成 DOM，本来就不支持 |
| 跨域小窗口里的表不能合并 | 同源策略限制 |
| 列表型表格只采到第一页 | 列表翻页尚未支持 |
| canvas 画的表格采不到 | 本质是图片，读不出文字 |

先排除这些，可以省掉一次往返。

### 第二步：打开调试控制台

去 **设置 → 隐私与诊断 → 调试工具**，打开「采集调试控制台」。

![隐私与诊断页的调试工具开关，默认关闭](/assets/table-flow/troubleshoot/privacy-diagnostics.webp)

开启后，采集浮动面板头部会出现「调试」按钮。

::: warning 平时请保持关闭
调试模式会额外记录运行诊断，还会启用页面级探针。它只在本地内存里存（关闭浏览器即丢弃），不发送到任何地方，但会占用一点性能。
:::

### 第三步：把出问题的操作再完整做一遍

**这一步不能跳过。**

调试控制台记录的是"你实际做了什么"。如果只是打开控制台就导出，文件里既没有出问题的表格、也没有那次失败的过程，开发者拿到的只是一个空壳——还是得回来问你。

所以请：

1. **别关页面**。停留在出问题的那个页面上。
2. **从头到尾重做一次**出问题的操作。比如：
   - 采集不到表格 → 重新点一次「重新扫描」
   - 翻页卡住 → 重新开始采集、翻到卡住的地方
   - 填充跳过字段 → 重新导入 Excel、选目标、跑到提示跳过那一步
3. **让问题真的发生一次**再停手。看到那句提示、看到失败的结果，就停在这里。

::: tip 复现时尽量少做无关操作
记录有条数上限（最近 1000 条）。如果你在出问题前后反复试了很多次，最早的线索会被挤掉。**一次干净的复现**比十次乱试有用。
:::

### 第四步：不要关页面，立刻导出报告

问题刚复现完，**马上**在调试控制台右上角「…」菜单点**导出报告**，得到一个 JSON 文件。

::: danger 这两件事会让数据消失
- **关闭浏览器 / 扩展被休眠** → 记录只在内存里，直接清零
- **关掉或刷新出问题的页面** → 当前的会话与表格现场没了

所以顺序必须是：**复现 → 立刻导出 → 再慢慢写信**。
:::

::: warning 发送前请自己过一遍
报告里除了运行诊断，还有 DOM 快照、页面信息等其它区块。诊断本身不含你的 Excel 值、网页原值和下拉选项文字，但**其它区块可能有**。发之前打开看一眼，删掉你不希望公开的部分。
:::

### 第五步：把提示语一起拍下来

导出文件是给机器看的，**面板上的那句提示是给人看的**，两者缺一不可。

复现时面板上出现的提示（例如「已跳过 1 个字段（保留网页原值）：B2 数量」），请**截图**或**把文字抄下来**一起发。很多问题光看这一句就能定位。

### 第六步：发邮件

发到 <2764574625@qq.com>，照这个模板填：

```text
【问题类型】采集 / 填充 / 激活 / 更新
【TableFlow 版本】在「设置 → 更新」或面板头部能看到，例如 <Fact product="table-flow" id="version.current" />
【浏览器】Chrome / Edge + 版本号
【卡在哪一步】选择表格 / 设置行列 / 检查映射 / 逐行填充
【现象】面板提示的完整文案（有截图最好）
【复现步骤】点了什么、期望什么、实际什么
【附件】调试控制台导出的 JSON（已自查）
```

**不需要提供**：具体网址、账号密码、表格内容。这些对定位没有帮助，反而有泄露风险。

### 为什么必须要那份 JSON

你可能会想：我描述得够清楚了，为什么还要折腾导文件？

因为很多问题**光看现象判断不了**。同一个"填充失败"，可能是网页控件只读、可能是下拉没有匹配项、也可能是 Excel 那一格是空的——这三种在面板上可能显示成相近的一句话，但导出文件里记的原因码不同，修法完全不同。**没有那份文件，就只能猜。**

### 什么样的问题描述最有效

| ❌ 效果差 | ✅ 效果好 |
|---|---|
| 「采集不了」 | 「点了采集，面板提示『未检测到表格』，但页面上明明有表格」 |
| 「填充失败」 | 「第 1 行填进去了，第 2 行提示『没有能匹配该值的选项』，仓库列的值是『成品仓』」 |
| 「不好用」 | 「虚拟滚动的大表，采到 994 行但页面显示 1000 行」 |

**关键差别**：有没有说清**面板提示了什么**。面板的提示语都是精心写的，它已经告诉你原因了。
